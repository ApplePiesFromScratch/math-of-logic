## Product

A poster. Input is a prefix. Output is:

```
G, V, mint, writes, lands or θ, leftover vs other G, two reads if two measures exist
```

The token string is one of the reads, not the object.

If the write leaves V, the line is θ and the token does not ship. That is `accountant.py` on the decode path.

## V, in public

- Type V listed for anything that will run (int, pile-count, volume, bool).
- Weight V: stamp IEEE if used; keep a Q-kernel path for the nets that fit.
- No silent Inf. Softmax underflow is θ, not a patched 0.

## G, stamped

- Score combinator named. Ship dot **and** one other (xor-shaped flipped winners on bits). Decode records which G ran.

## Train on writes, not only on school credits

Ω is not just “next token from the internet.”

Each example is a merge with **two reads** when two measures exist:

```
writes loc=front
reads school+=4  count=1
```

Loss is leftover on **both** reads, posted on one line.  
If I only train the 4, I rebuild the Platonist.

Also in Ω:
- leaks that must θ (OOV, `0/0`, empty prefix)
- two compose-orders with leftover kept (path A vs path B)
- two mints that val-eq and must stay two lines (`(9,6)` x² vs 3x)

Human web text can stay as a language read. It does not get to be the only credit.

## Step and audit

SGD is iterate-`S` on weight letters. Every k steps the journal posts:

```
mint = seed + step + data-slice
train L
test L
leftover
G version
```

One number “loss” does not post. Empty slice is θ, not 0.

Checkpoints are mints. Never val-eq two seeds into “the model.”
